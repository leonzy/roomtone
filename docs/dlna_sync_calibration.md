# DLNA 设备同步补偿

DLNA 设备设置的 `dlna_sync_delay_ms`（0–2000 整数毫秒，默认 0）描述它相对原生 AirPlay 的额外出声延迟。它不是给 DLNA 再加等待时间；不自动猜测型号延迟。

多个非待机成员播放时，以配置值最大的 DLNA 为参考，给每台成员添加 `最大 DLNA 配置值 − 该成员配置值` 的补偿；非 DLNA 的配置值按 0 处理。仅一台成员、或组内没有 DLNA 时不添加补偿。旧成员 `delay_ms` 保留为接口/存储兼容字段，不再参与播放，避免重复补偿。

例：小爱 1000ms、另一个 DLNA 600ms、两个 AirPlay，实际增加的补偿分别为 0、400、1000、1000ms。小爱单独或书房单独播放均不增加补偿。

配置保存在设备行，重新发现只更新设备能力/地址，不覆盖用户设置；重新编组按成员设备设置重新计算。Lynx 入口是 DLNA 设备设置或区域设置中的该 DLNA → **DLNA 同步补偿**，编组面板只选择成员。输入和滑块编辑草稿，保存只更新这个字段，失败显示原因，不显示成功。

推送输出以实际 PCM 静音和时间戳实现补偿；拉流输出按计划起播偏移实现，可靠进度反馈保留已应用的偏移。保存时推送成员可立即调整；多 DLNA 的拉流偏移在下一次播放/继续/切歌完整应用。暂停/停止仍并发下发，不人为增加命令延迟。普通 DLNA 缓冲可能变化，本配置不承诺样本级同步。
